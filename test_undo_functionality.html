Understanding the Undo Error

The error you're seeing is expected behavior when there's no undo history available.

When Undo Works:

  • ✅ After moving tags from "Available" to "Selected"
  • ✅ After moving tags from "Selected" to "Available"
  • ✅ After using "Select All" to add all available tags
  • ✅ After using "Clear All" to remove all selected tags

When Undo Doesn't Work:

  • ❌ When no moves have been made yet
  • ❌ After using the "Clear Filters" button (clears undo history)
  • ❌ After uploading a new file (starts fresh)
  • ❌ When the undo stack is empty

Test Steps

To test the undo functionality:

  1. Upload an Excel file with product data
  2. Select some products from the "Available" list
  3. Click the "Undo" button - it should restore the previous state
  4. Try clicking "Undo" again without making any moves - you'll get the "No undo history" message

Error Explanation

The error you encountered:

POST http://127.0.0.1:5002/api/undo-move 400 (BAD REQUEST)
{error: 'No undo history available'}

This means:

  • The undo stack in the session is empty
  • No previous moves have been made to create undo history
  • Or the undo history was cleared by using "Clear Filters"

This is normal behavior! The undo button only works when there are previous actions to undo.
